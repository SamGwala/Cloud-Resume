Problem

Most auto-remediation fails in one of two ways. It reports success because a restart command returned 0 while the service is still down or it retries forever and turns a small fault into a larger one. SkyGuard is a reusable platform for running containerised workloads on AWS, built around avoiding both.

Architecture

SkyGuard is designed as Terraform modules that provision standardised networking, compute, IAM, monitoring and per-environment infrastructure. CloudWatch alarms and health checks raise events through EventBridge to a Lambda function, which classifies the incident, adds operational context, and selects a remediation based on severity and the workload’s recovery history. Systems Manager carries it out as a service restart or an instance replacement. Recovery is then validated against application health; if validation fails, the platform tries the next step or escalates once retry thresholds are exceeded. Every incident is recorded in DynamoDB, and Grafana dashboards cover availability, error rate, latency and recovery performance. The status table below shows what is built today.

Engineering decisions

  • Validate the outcome, not the command. A successful SSM execution proves a command ran. Application health decides whether the incident is resolved.
  • Bound the automation. Retry thresholds stop restart loops and define when a human takes over.
  • Choose remediation from context. Severity and recovery history decide between a restart and a replacement. A third identical restart is rarely the right answer.
  • Keep incident history. State, workload, actions, attempts and outcomes are stored, so repeat failures are visible and past results inform the next decision.
  • Remove SSH from the access model. Administration goes through Systems Manager, IAM roles are scoped per function, and secrets are managed rather than embedded.

Delivery and reliability

The delivery pipeline is designed around GitHub Actions: Terraform validation, infrastructure security checks, application tests, image builds and scans, deployment, and post-deployment health validation. Reliability is tested through planned failure scenarios: application crashes, service failures, resource exhaustion, unhealthy instances, failed remediation, failed deployments and repeated incidents. A configuration-driven onboarding model lets new workloads use the platform without copied infrastructure.

Problem. A single EC2 workload that failed or ran hot would go unnoticed until a user complained, and fixing it meant opening SSH access.

Solution. Terraform provisions an Ubuntu workload with CloudWatch alarms on sustained CPU, SNS notifications, and automated recovery through Systems Manager. Remote state lives in S3 with locking so applies can’t collide. Alarms fire on sustained load, not spikes, to keep alerts meaningful. A budget alert caps surprise cost.

Outcome. It established the patterns SkyGuard scales up.
